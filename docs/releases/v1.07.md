# AirCtrl-Desklet 1.07

Version 1.07 verlegt die vollständige Lua-Automatik vom Desklet in den zentralen,
weiterhin Qt-freien `airctrl-server`. Dadurch laufen Zeitpläne und Ereignisregeln
auch dann weiter, wenn kein Desktopclient geöffnet ist.

## Server als einzige Lua-Instanz

- Lua 5.4.9 wird nur noch in den Server eingebunden; Client und Desklet enthalten
  keine Lua-Laufzeit.
- Das maßgebliche Skript liegt standardmäßig unter
  `$HOME/.config/airctrl-server/automation.lua` auf dem Server.
- Aktivierung, Skriptrevision und bereits behandelte Zeitplantermine werden in
  `$HOME/.config/airctrl-server/automation-state.json` gespeichert.
- Lua-Aufträge benutzen im Server dieselbe Positivliste, serialisierte
  Gerätewarteschlange und anschließende Statusbestätigung wie Clientbefehle.
- Skript, Zustandsdatei und Verzeichnis können optional im Abschnitt
  `[automation]` von `/etc/airctrld.cfg` festgelegt werden.

## Editor auf den Clients

- Beim Öffnen fordert das Desklet eine serverweite Editier-Sperre an.
- Nach erteilter Sperre überträgt der Server das aktuelle Skript und seine
  Revision zum Client.
- **Auf Server speichern und neu laden** sendet den Text zurück. Erst der Server
  prüft Größe, Lua-Syntax und API, speichert atomar und lädt die neue Fassung.
- Gleichzeitig darf genau ein TCP-Client bearbeiten. Weitere Clients erhalten
  eine verständliche Ablehnung.
- Abbrechen oder der Abbruch der TCP-Verbindung gibt die Sperre automatisch frei.
- Eine Revisionsprüfung verhindert das Überschreiben einer zwischenzeitlich
  geänderten Serverfassung.

Eine vorhandene lokale `automation.lua` aus v1.06 bleibt als Sicherung auf dem
Client erhalten, wird aber nicht automatisch auf einen möglicherweise entfernten
Server kopiert. Eigene Regeln deshalb einmal aus der alten Datei in den neuen
Editor übernehmen und bewusst auf dem Server speichern. Die Serverautomatik ist
bei einer Standardinstallation zunächst deaktiviert.

## Protokoll und Diagnose

Das TCP-Protokoll besitzt neue Nachrichten für Status, Sperranforderung,
Speichern und Freigeben. Normale Zustandsmeldungen enthalten nur Lua-Diagnosen;
der Skripttext wird ausschließlich an den Client mit erteilter Sperre gesendet.
Die Desklet-Diagnose zeigt nun ausdrücklich Serverpfad, Server-Lua-Version,
Revision, Zeitpläne sowie letztes Ereignis und letzte Aktion.
