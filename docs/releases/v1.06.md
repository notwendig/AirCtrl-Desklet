# AirCtrl-Desklet v1.06

v1.06 trennt Geräte- und Clientkonfiguration vollständig.

Die Quellen liegen getrennt unter `src/server` und `src/client`; unter
`src/common` verbleibt nur die Qt-freie Versionsvorlage. Der Server benötigt
kein Qt und verwendet C++17/POSIX-Sockets sowie nlohmann/json.
Vier CMake-Presets bauen Server und Clients unabhängig nach
`build/{DEBUG|RELEASE}/{server|client}`.

## Server

- `airctrl-server` ist der einzige Prozess, der `AC2729-10:5683` kennt und
  per UDP/CoAP mit dem Gerät kommuniziert.
- Listenadresse, TCP-Port, Geräteadresse, UDP-Port sowie Wiederverbindungs- und
  Statusfristen stehen ausschließlich in `/etc/airctrld.cfg`.
- Standardmäßig lauscht der Server auf TCP-Port 5680.
- Alle Clients teilen weiterhin genau eine Geräte-I/O-Sitzung, einen UDP-Socket
  und den synchronisierten Protokollzustand.
- Nach einem endgültigen Status-Timeout wird nur die Geräte-I/O geschlossen und
  neu geöffnet; zuvor wird Observe einmal auf derselben Sitzung erneuert.
  Verbundene TCP-Clients bleiben erhalten.
- Nachprüfung am 13. September zeigte verworfene, verzögerte Observe-Pakete an
  dynamischen UDP-Zielports. Der Server verwendet deshalb einen konfigurierbaren
  festen lokalen UDP-Port, CoAP-Keepalives und genau eine Neuanmeldung auf
  derselben Sitzung, bevor er Socket und Synchronisierung ersetzt.

## Clients

- Desklet, Lua und `airctrl-client` kennen ausschließlich Serverhost und TCP-Port.
- Damals vorkonfigurierter Serverhost, Port `5680`; ab v2.00 ist `localhost` der Standard.
- Das Desklet startet keinen Serverprozess mehr selbst.
- Alte gespeicherte Geräteschlüssel werden beim nächsten Speichern entfernt.
- Gleichbleibende Alarmidentitäten lösen keine wiederholten Lua-Alarmereignisse
  nur wegen eines veränderten Sekundenwertes im Meldungstext aus.
- Ein frischer Build bettet die vollständige Lua-Beispielautomatik wieder ein;
  die Editorvorlage hängt nicht mehr von einem vorhandenen CMake-Cache ab.

## Installation und Sicherheit

`install.sh --server` baut nur den Qt-freien Server, installiert ihn standardmäßig
unter `/usr/local/bin`, legt `/etc/airctrld.cfg` bei
der ersten Installation mit Root-Rechten an und erhält eine vorhandene
Administratorkonfiguration. Der systemd-Benutzerdienst startet den Server
ausdrücklich mit dieser Datei. `install.sh --client` baut und installiert nur
Desklet und CLI. Ohne Rollenoption werden weiterhin beide Seiten installiert.

Gültige Gerätestati werden nun mit UTC-Zeitstempel und stabiler CSV-Kopfzeile an
`/var/log/airctrl.log` angehängt. Der Installer richtet Dateirechte und eine
Größenrotation ein. Das mitinstallierte `airctrl-plot` erzeugt für numerische und
boolesche Spalten eine mehrseitige PDF mit vier Diagrammen pro Seite.

Das TCP-Protokoll hat keine eigene Anmeldung oder Verschlüsselung. TCP-Port 5680
darf nur für vertrauenswürdige Rechner im lokalen Netz freigegeben werden.

Das Einspielskript prüft das entpackte Paket vollständig, bevor es das saubere
Git-Original verändert. Es verwendet weder Force-Push noch Mitschnittdateien.
Es erstellt den annotierten Tag `server_clients` am geprüften Commit und pusht
Branch und Tag atomar. Ein bereits veröffentlichter Tag `v1.06` wird nicht
verschoben; nur wenn er noch fehlt, wird er am selben Commit zusätzlich erzeugt.
Der CI-Workflow überwacht den tatsächlich veröffentlichten Branch `master`.
Ein sauberer, aber abweichender lokaler `master` wird nicht rebased: Die
Veröffentlichung baut direkt auf `origin/master` auf, und der alte lokale Stand
bleibt auf einem Sicherungsbranch erhalten.

Die eigenen C++-Header sind auf Englisch im Doxygen-Stil dokumentiert. Mit
`doxygen Doxyfile` kann optional eine lokale HTML-Referenz erzeugt werden;
generierte Dokumentation bleibt außerhalb von Git und Quell-ZIP.
